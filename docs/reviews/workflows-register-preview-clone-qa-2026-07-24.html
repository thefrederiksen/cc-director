The ask

After the Shared Workflow Library shipped, the owner reviewed the cockpit's Workflows register and named two shortcomings: people should be able to SEE a workflow's actual conduct without leaving the list (a preview popup), and they should be able to CLONE any workflow - built-ins included - right from the list, because "take our mission, clone it, and change it" is the whole customization story. The detail page already carried Clone; the register, where people actually meet the library, offered nothing but the on/off switch.

What was built

  • Preview on every row: a popup showing the workflow's shape - name, badges, version, when to use it, the human checkpoint, the steps - and the FULL conduct markdown, scrollable, rendered through the same sanitized renderer the detail page trusts. The conduct is fetched pinned to the version the row reported (the detail page's torn-read discipline, which also keeps the preview working for a workflow that is turned off).
  • Clone on every row and inside the preview: the same confirm-then-copy flow the detail page has - the dialog proposes <id>-copy, confirming calls the Gateway's clone and navigates to the new copy, and a refusal lands in the page's error state, never silently.
  • The preview is not a dead end: "Open full page" and "Clone" live inside it, so the read-then-decide moment happens on one screen.

Cockpit-only - no Gateway changes; the conduct read and the clone route were already live from the Shared Workflow Library work earlier today.
