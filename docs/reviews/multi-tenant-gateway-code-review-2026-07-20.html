Bottom line. Today’s code is careful, well-tested, and written in the project’s deny-by-default style. The dangerous problem is not “today’s commits are sloppy” - it is that multi-tenant isolation is still only partly installed. Foundations land correctly; adoption into the fourteen session-keyed collections and the remaining hosted surfaces has not finished. Charging customers (or turning voice on) before those close would re-open real cross-tenant leak paths that the team has already booked.
What is genuinely good. The three-outcome entitlement model, the typed removal payload, the physical partition in TenantSessionMap, the ownership-safe self-host journal, and the admit-list voice sweep are senior work. Tests that pin both “the victim survives” and “the owner really was cleared” (destructibility controls) are exactly the right shape for multi-tenant code.

4. What landed well

  • Typed partition keys, not conventions. TenantSessionKey cannot be built without a resolved TenantId. TenantSessionMap has no string overload. A missing tenant fails at compile time, not at runtime after a silent collision.
  • Injectivity discipline. No trimming, no case folding, whitespace refused rather than cleaned - so two distinct session identifiers never become one key.
  • GetOrAdd with a single winner. The map does not trust ConcurrentDictionary.GetOrAdd’s multi-run factory; it uses TryAdd so seed markers and first-seen clocks stay unique under contention.
  • Director removal carries the owner. DirectorRemoval(TenantId, string) makes an unscoped removal inexpressible at the event boundary. The roster-cache forget is now structurally scoped.
  • Faulting subscribers cannot kill the Gateway. RaiseDirectorRemoved invokes each handler independently with a try/catch, so one store failure cannot abort the process or starve later handlers.
  • Entitlement is three-state, not boolean. Entitled / NotEntitled / Unknown correctly separates “looked and unpaid” from “could not look”. Hosted enrollment maps those to 200 / 402 / 503 and never mints on ignorance.
  • Self-host transaction is ownership-safe. Resume journal + Owned-only rollback is the right model for provisioning a stranger’s machine. Keeping the card disabled until proven is honest product engineering.
  • Voice sweep admits only canonical upload directories. Refuse-list thinking would delete a future sibling; the admit-list only deletes what this store itself writes.

5. Priority 0 - block go-live / security floor

These are not all introduced today, but they are the multi-tenant manager’s real readiness bar. Several are already open on GitHub. Today’s work does not close them.

P0
1. TenantSessionKey / TenantSessionMap are not adopted into production
Today: df078618 - state half only. Production Gateway still uses bare session-identifier dictionaries.

Where
Types live under src/CcDirector.Core/Tenancy/. Grep of origin/main shows production use is limited to the types themselves and their unit tests. Gateway stores still declare ConcurrentDictionary<string, ...> for session state.

Why it matters
The type exists because fourteen retained collections can collide across accounts that present the same raw session identifier. Shipping the type without rewiring those collections does not reduce risk; it only documents it. On a multi-tenant Gateway this is still cross-tenant overwrite / suppress / delete.

Improvement
Adopt the map into the collections the type comment lists (needs-you clock, both transcribing markers, governance state emitter, turn-end watcher, statistics indexes, concurrency set, turn-brief caches) in small, tested pull requests - one store family per pull request, with a two-tenant collision test for each.

P0
2. Voice paths still hard-code the local tenant
Open: #1890, #1893. Confirmed on origin/main in GatewayWingmanVoiceEndpoint.

Where
Multiple calls of the form voice.Get(TenantId.Local, sid), voice.Mark(TenantId.Local, sid), voice.StoreSpokenAsync(TenantId.Local, ...). Background loops and the verb path both do this.

Why it matters
Voice state was partitioned (#1915), but the routes that drive it still write and read the local partition. On hosted, account voice is dead or wrong; turning the synthesis key on before these resolve would also arm a leak (already called out in today’s hosted quality-assurance report).

Improvement
Resolve request / bound-connection tenant on every voice route and every background voice loop (via ITenantPass). Do not put a provider key in the vault until both are proven live with two accounts.

P0
3. Dictation / utterance upload family is still unpartitioned
Open: #1884, #1896, #1897.

Why it matters
Recorded speech and plaintext transcripts on shared infrastructure. A replayed idempotency key can hand one account another’s transcript. This is the highest-value data the product ever holds.

Improvement
Partition staging, delivery records, archive, and telemetry by tenant before any multi-tenant dictation is enabled. Pair with the voice sweep so abandoned audio under a future partition is still bounded.

P0
4. Residual bare Director-id routes and credential-less register
Open: #1866. Code still documents TryResolveLegacyKey and Get(string) as temporary.

Why it matters
Composite registry keys only help callers that pass a tenant. Legacy bare-id lookup answers with the freshest match across tenants - deliberately, to avoid a denial-of-service via collision - which means cross-tenant addressing still exists on every route not yet converted.

Improvement
Convert remaining /directors/{id}/... and related surfaces to Get(TenantId, string) from authenticated request tenant. Kill or host-deny the credential-less HTTP register path on hosted.

P0
5. Fleet-wide aggregates and owner-settings surfaces are still tenant-blind
Open: #1924, #1932, #1917, #1863, #1921, #1923, and related.

Why it matters
Any enrolled tenant can still reach diagnostics rollups, launcher/machine control, brain restart, AI model spend routes, stream write with caller-supplied ids, and more. Isolation of the roster is worthless if a side door rewrites another account’s world.

Improvement
Keep the deny-list approach for owner-only routes on hosted until each has a real tenant model. Prefer permanent deny for operator surfaces that have no multi-tenant product meaning.

P0
6. Device keys stored in plaintext on shared storage
Open: #1878.

Why it matters
Bearer secrets for every tenant in one readable file. Compromise of the share is compromise of every account’s tunnel and cockpit cookie.

Improvement
Hash at rest (or per-tenant sealed storage). Treat device keys like password hashes: compare digests, never serve the raw secret back after mint.

P0
7. Hosted mode signal is a mutable environment flag
Open: #1868.

Why it matters
Losing CC_GATEWAY_HOSTED collapses every tenant into the single-tenant shape. That is a silent, fleet-wide isolation failure, not a loud crash.

Improvement
Fail closed when the deployment is the hosted image but the flag is absent or wrong (image-baked marker, or refuse boot if Postgres multi-tenant schema is present without hosted mode). Never silently become Local for everyone.

P0
8. Do not enable voice synthesis until partition is complete
Documented today in hosted quality-assurance report (#1926 follow-up prose).

Why it matters
The 503 message currently invites operators to add a vault key. Doing so would produce audio and transcripts the code is not ready to isolate.

Improvement
Change the error text so it does not invite a config fix. Keep the key out of the vault until P0 voice and dictation items above are green on a two-account live proof.

P0
9. Session owner cache and transcribing marks are still bare-session maps
Production: SessionOwnerCache, TranscribingSessions.

Why it matters
Two accounts with the same session identifier share owner routing and the orange “transcribing” mark. That is wrong routing and wrong UI, and it is the exact failure class TenantSessionMap was built to prevent - but these stores were not converted today.

Improvement
Rewire both onto TenantSessionMap (or equivalent partition) as part of the adoption series in finding 1.

6. Priority 1 - bugs and incomplete work from today’s code

P1
10. Fleet session-number allocator is still not tenant-scoped
Today: #1942 fixed roster forget; allocator left explicitly unscoped.

Where
FleetSessionNumberAllocator.ReleaseForDirector(string) and GatewayHost wiring: Registry.OnDirectorRemoved += removal => SessionNumbers.ReleaseForDirector(removal.DirectorId); Comments on the allocator admit: one tenant’s removal can free another’s numbers.

Why it matters
Not a data leak, but a real multi-tenant correctness bug: duplicated rail numbers across accounts, and stolen free-list entries. The tenant is already on the event; the subscriber throws it away.

Improvement
Partition pool + assignment record by tenant. Change ReleaseForDirector(TenantId, string) and every Allocate/Adopt call site to pass the bound tenant. Add a two-tenant shared-director-id test that removal of A does not free B’s numbers.

P1
11. Today’s removal path logs the raw tenant identifier
Violates the project’s own TenantId.ToLogString() rule.

Where
DirectorRegistry.RaiseDirectorRemoved: tenant={key.Tenant.Value}
FleetRosterCache.Forget: tenant {tenant.Value}

Why it matters
Account tenant ids are stable GUIDs tied to billing subjects. The type system already provides a one-way short tag for logs. Raw values in shared hosted logs expand the blast radius of a log leak and break the privacy contract the rest of the tenancy stack is written around.

Improvement
Replace both with tenant.ToLogString(). Add a small test or analyzer rule that new FileLog lines do not interpolate .Tenant.Value / raw account tenants.

P1
12. Voice age sweep does not cover future tenant partitions
Today: #1952. DirFor is still flat: Path.Combine(_root, uid).

Why it matters
The sweep correctly skips the tenants container name so it will not delete the whole partition tree. That is good for today. When dictation/voice staging moves under tenants/<tenant>/<upload>, abandoned audio under those paths will never be swept - unbounded retention returns, only nested one directory deeper.

Improvement
When partitioning lands, either (a) sweep each tenant partition with the same admit-list rules, or (b) keep a single flat staging root and put only durable artifacts under tenant partitions. Land the sweep change in the same pull request as the path change - never as a follow-up.

P1
13. Hosted Director-removal no longer clears snoozes
GatewayHost wires: clear only when not hosted.

Why it matters
On hosted, removed Directors leave snooze rows as durable tombstones forever (until live-session prune). That is a bounded leak of disk/table growth, and it can re-apply hold semantics if a session id is reused later under the same tenant. The comment explains why (background thread, no ambient tenant) but the product gap remains.

Improvement
Teach SnoozeRegistry.ClearForDirector(TenantId, string) using the tenant now present on DirectorRemoval. Re-enable the subscriber on hosted. Same pattern as the roster fix.

P1
14. Bare capability maps on DirectorRegistry still keyed by director id only
_everReachable, _stateReporting.

Why it matters
Comments claim these are process capability flags with no client-served content. Still, two tenants with the same director id share those flags: one account’s stream Hello can mark the id state-reporting for the other. On hosted that is real cross-tenant influence of reconcile-poll skip behavior.

Improvement
Key both by DirectorKey (tenant + id), or store the flag on the DirectorDto entry itself so it cannot outlive the wrong partition.

P1
15. HTTP register still stamps Local and remains a collision surface
Documented in TryResolveLegacyKey / Upsert (http).

Why it matters
Comments say Local-keyed HTTP entries are “served to no account” on hosted - good for reads that are tenant-aware. They still pollute bare-id legacy resolution and can participate in freshest-match behavior for unconverted routes.

Improvement
On hosted, refuse HTTP register/heartbeat entirely (401/404). Keep the path for self-host only. That shrinks the legacy surface the conversion work has to reason about.

P1
16. Tenant email is write-once at mint; later logins never refresh it
TenantRegistry.MintOrLookupBySubject.

Why it matters
Email is stored only on a fresh mint. An account that first enrolled with a token that carried no email keeps a null email forever, even after later enrollments supply one. Hosted account status then reports “identity not available” for a fully valid tenant (#1856 shape). Not a security hole; it is a product lie that confuses dogfood and support.

Improvement
On existing lookup, if the row’s email is null and the call supplied a non-empty email, update the row. Never change the subject or tenant id. Still never use email as a key.

7. Priority 2 - correctness and maintainability

P2
17. Entitlement schema guard is defense-in-depth only - do not over-claim
Today: #1954. Commit message correctly reframe as non-fix for emitted SQL.

Why it matters
Good change, good tests. Risk is future readers treating it as “we fixed enrollment 503s” when the real 503 path is still operational (database down, missing grant, missing row data). The diagnostic SqlState/MessageText is the valuable half.

Improvement
Keep the guard. Wire an operator dashboard or alert on repeated READ FAILED ... UNKNOWN lines - that is the real production symptom.

P2
18. TenantId construction trims; identity systems may disagree
Open: #1854.

Why it matters
Constructor trims whitespace. Downstream path segments, hashes, and external systems that do not trim will disagree. Multi-tenant path partitions that embed tenant.Value (prompts, voice archive, turn jobs) inherit that disagreement.

Improvement
Canonicalize once at construction (trim + reject internal whitespace + maybe lowercase for GUID form) and document the single form. Align path partition helpers with that form.

P2
19. Self-host orchestrator is excellent but still unproven on a machine
Today: #1928. Card remains disabled; tests are pure harness.

Why it matters
Transaction logic is well covered. Real steps (download, tray install, enroll) are not. Enabling the card without an isolated-box proof is how you half-provision a customer.

Improvement
One scripted install on a clean Windows VM that runs the real compensations (including deliberate mid-step kill). Only then remove the disabled badge. Keep ownership rules as-is.

P2
20. Corrupt self-host journal fails open to empty
SelfHostJournal.FromJson swallows parse errors.

Why it matters
Documented: better a repeated step than a dead connect screen. Cost: ownership memory is lost, so a later failure might not undo something a prior run created, or might re-run a step that is only mostly idempotent.

Improvement
On parse failure, keep a side file journal.corrupt.<timestamp> for support, log loudly, and still start fresh. Consider a schema version field so future format changes do not look like corruption.

P2
21. TenantPass known-tenants list is push-store-only
TenantPass uses PushedSessionStore.KnownTenants.

Why it matters
Background sweeps only visit tenants that currently have a live Director stream. A tenant with durable work but no live Director (pending voice, pending dictation, durable snooze) may never be visited by some loops. Correct for push-driven fleet sweeps; wrong if reused for durable job drains.

Improvement
Split “live fleet tenants” from “tenants with durable work”. Job stores should enumerate their own partitions, not depend on the push store.

P2
22. Hosted identity assertion intermittent failure still open
Today: #1929 improved diagnostics; #1894 remains open.

Why it matters
The louder assertion is the right temporary instrument. A multi-tenant suite that sometimes sees a foreign email is either a real isolation bug or a test-harness leak. Either way it undermines confidence in the rest of the isolation proofs.

Improvement
Use the next red full-suite run to name the source, then fix root cause (shared fixture, static cache, ambient tenant bleed). Do not weaken the assertion.

8. Priority 3 - polish

P3
23. Comment-to-code ratio is very high

The prose is excellent and has prevented real mistakes (schema guard reframe, ownership rules, admit-list sweep). Still, some files are harder to scan than they need to be. Prefer keeping the non-obvious “why” and folding repeated deny-by-default sermons into one architecture page that types link to.

P3
24. TenantSessionKey.Value is powerful but easy to misuse as a path

Docs say it is a dictionary key, not a path segment, and For() rejects separators. Still easy for a later author to put key.Value into a filesystem path. Consider a distinct type or analyzer for “storage key vs path segment” if adoption spreads.

P3
25. Self-host progress messages are good product copy - keep them centralized

SelfHostOrchestrator.Describe is the right single place. When the card enables, wire UI progress exclusively through that API so screens never invent their own step names.

P3
26. Review artifacts and dogfood docs should state image digest always

Today’s quality-assurance report already does this well. Keep that rule for every hosted proof: merged on main is not deployed. Do not delete “does not work yet” lines until seen on the running image.

9. Suggested order of work

  1. Stop digging. Do not put the voice synthesis key in the vault. Soften any error text that invites that config change (P0 #8).
  2. Close the removal-event family. Tenant-scope the session-number allocator and hosted snooze clear using the tenant that is already on DirectorRemoval (P1 #10, #13). Cheap, same pattern as today’s roster fix.
  3. Adopt TenantSessionMap into the fourteen session stores in small batches with two-tenant collision tests (P0 #1, #9).
  4. Voice + dictation full partition (routes, loops, staging, archive) with sweep coverage for the new paths (P0 #2, #3; P1 #12).
  5. Kill hosted legacy Director-id surfaces (P0 #4; P1 #14, #15).
  6. Hosted deny ledger for owner/operator routes until each has a real model (P0 #5).
  7. Device key at-rest hardening and hosted-mode fail-closed (P0 #6, #7).
  8. Self-host real-machine proof, then enable the card (P2 #19).
  9. Polish: raw-tenant log scrub (P1 #11), email refresh (P1 #16), TenantId canonicalize (P2 #18).

11. Closing note

Today’s multi-tenant work is high quality. The team is building the right kinds of primitives: typed keys, three-state entitlement, ownership-safe provisioning, and removal events that cannot drop the owner. The risk is sequencing - foundations land, while production stores and hosted side doors still speak the single-tenant dialect.

Treat “merged to main” and “safe to charge for hosted” as different bars. The code reviewed today advances the first. The priority-0 list is the second.
