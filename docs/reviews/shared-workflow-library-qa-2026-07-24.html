Built-in DevThrottle workflows restored to every hosted tenant - five phases, four merged pull requests, one live deploy, independently verified

All five phases are delivered, merged to origin/main, deployed to the live hosted Gateway, and independently verified against it with a real tenant. The mission workflow - and the whole built-in DevThrottle library - is back for every tenant, current and future, with zero per-tenant provisioning. One finding: the locally INSTALLED command-line tool predates today's merges (it ships with the desktop app, not the Gateway), so its clone verb arrives with the next desktop release; the Gateway routes and the cockpit already serve clone live today.

What was broken

When DevThrottle moved from the local Gateway to the hosted multi-tenant Gateway, the out-of-the-box workflows - Mission, Standalone, and Standalone with review - disappeared from every tenant's catalog. The built-ins were seeded once at Gateway boot into the reserved System partition (the store constructor is the only caller of the seeder, and it runs inside the startup System scope), while every signed-in tenant's requests read the tenant's own partition through the Entity Framework tenant filter. The two partitions never met: every hosted tenant saw an empty catalog, no session briefing carried the workflow index, and the mission-create path could not resolve the mission workflow. Newly minted tenants got nothing at all.

Before (live hosted Gateway, captured 2026-07-24 15:11 UTC, commit 408f7fd):
  • cc-devthrottle workflow list against gateway.devthrottle.com (a real signed-in tenant): an EMPTY table - zero workflows.
  • GET /gateway/workflows/mission/instructions with the tenant's device credential: HTTP 404.

The owner rulings this work implements (2026-07-24)

  • Shared central library: the built-ins live ONCE in the shared library partition and every tenant's catalog serves them read-only in union with the tenant's own workflows. Never copy-per-tenant. A DevThrottle update reaches every tenant at once.
  • Built-ins are read-only everywhere (reversing the 2026-07-17 editable-with-reset ruling). They update only by shipping a new Gateway; reset-to-shipped is retired.
  • Customize by cloning into a tenant-owned, fully editable copy with provenance recorded.
  • Per-tenant off switch kept: off hides and refuses seats for that tenant only, never deletes.
  • Zero provisioning: a brand-new tenant's first read serves the library. There is no seeding step to forget.

The zero-provisioning guarantee, proven on a real tenant

This tenant never had a workflow row written for it - its catalog was empty for the whole life of the hosted Gateway (the before evidence above). No seeding step, no backfill, and no migration wrote anything into this tenant's partition for the built-ins. The library appearing on the first read after deploy is therefore exactly the guarantee every FUTURE tenant gets: sign up, and the DevThrottle workflow library is simply there.

Defects found during the run

  • Command-line version skew (found by the independent verifier, not a Gateway defect): the installed tool on the verification machine predates today's merges, so its verb set is behind the live Gateway - reset still present (now a Gateway not-found), clone absent even though the Gateway's own refusal message points at it. Cause: the command-line tool ships with the DESKTOP application and only updates with a desktop release, while the Gateway deploys independently. Remediation: the next desktop release (the normal release-manager flow) carries the corrected tool from merged main. Until then the cockpit Clone action and the raw Gateway route both work.
  • Reliability observation: one 15-second Gateway timeout on the first enable attempt during live verification; the immediate retry succeeded and nothing was left inconsistent. Recorded, not blocking.
  • No Gateway-side defects were found: every claim about the deployed service was confirmed by independent live evidence, including the adversarial negatives (reserved-id refusal, write refusal, off-state conduct refusal).

What remains open (not defects)

  • The session-briefing workflow index on any given Director refreshes on Gateway-connect and on its refresh timer; a Director that has not reconnected since the deploy serves its last cache (up to the 24-hour staleness ceiling) before picking up the library index.
  • The architecture document (docs/architecture/shared-workflow-library-plan-2026-07-24.html) is untracked by design; the durable record is devthrottle_internal issue 514 and the merged pull requests.
  • The workflow library is the seed of a growing catalog: adding the next DevThrottle-maintained workflow is now one entry in BuiltInWorkflows plus a shipped binary - no tenant work at all.
