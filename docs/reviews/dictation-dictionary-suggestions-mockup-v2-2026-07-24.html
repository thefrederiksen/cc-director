Design review - round 1

Dictation dictionary suggestions: all five screens

CORRECTION, 2026-08-07 (owner ruling, issue 2481). The mockups below show the Vocabulary hint as "Terms biased into speech-to-text." That is wrong and the shipped page no longer says it. Nothing in the dictionary is ever sent to the speech-to-text provider - it is given audio only - because priming the transcriber changes wording and sentence structure and corrupts the record of what was said. The terms are corrected on the finished transcript afterwards. These mockups are left as the dated record of the 2026-07-24 review.

The feature in one sentence: the gateway keeps your dictation transcripts for 30 days, notices the words the speech model keeps getting wrong, and offers them as one-press dictionary additions - on the Dictionary page, in the daily email, and over the API.

Every screen below is drawn in the real Cockpit design system (tokens, left rail, and the existing Dictionary page sections lifted from the shipped app), so what you approve here is what the built page will look like. Evidence counts are the real figures mined from two months of dictation history. Covers devthrottle issues 2075 and 2074, on top of the storage foundation in internal issue 509.

Pressing Add writes each ticked term into BOTH sections at once: the term itself into Vocabulary, and its observed wrong spellings into Common mistranscriptions. That is the whole payoff - the user gets the full fix without understanding the two mechanisms.
  • The red count on the Dictionary nav item is the number of pending suggestions. It is the only attention signal in the whole design - no popups, no toasts. It clears when the queue is empty.
  • Evidence on every row. "heard as Mindsee, Mindsy... wrong 53 of 97 times" is what makes the suggestion trustworthy. The user never has to wonder why a term is offered.
  • Untick and Dismiss are different acts. Unticking skips a term this round but it may return with more evidence; Dismiss is permanent (until restored on screen 3). The v1 mockup conflated these - this is the main behavior change in v2.
  • Everything is pre-ticked because the ranked list is already filtered to high-confidence terms. The happy path is exactly one press.
  • Add uses the green button - the same green as the existing Save on this page, because it is the same kind of act (writes the dictionary). Red is reserved for attention, never for actions.

Dismissals are stored per tenant next to the suggestions themselves, so they survive across devices and are honored by the API exactly as by this page.
  • Evidence stays attached even after dismissal ("was heard as Cooper Netties"), so the user restoring a term months later remembers why it was offered.

  • This section renders only when opened from the "Dismissed terms" link - it is not a permanent third section fighting for attention on the page.

Dictionary suggestions

How DevThrottle learns which words to suggest for your dictionary.

Keep my transcripts to power suggestions
Stores the raw and cleaned text of each dictation for 30 days (newest 10,000 kept). Only your account can read them. Used for one thing: spotting words the model keeps getting wrong so we can suggest dictionary fixes. Turning this off stops new storage and deletes everything already stored.
Suggestions in my daily email
When new suggestions are waiting, include them in the daily report email with a link to review. Never more than one mention per day; nothing is ever added automatically.
Stored transcripts
1,847 transcripts stored - oldest is 29 days. Delete all stored transcripts now
  • Opt-out deletes, not just stops. That is the deliberate design decision this screen exists to get approved: off means gone, so the promise is one sentence with no residue to explain.
  • Both toggles default on. The feature only helps people who never open settings, so it must work for them - and the 30-day window plus tenant isolation is the guardrail that makes default-on defensible. Flip to default-off here if you disagree; it is a one-word change at this stage.
  • The stored count row is the receipt. "1,847 transcripts - oldest is 29 days" quietly proves the retention promise is real, and the delete link gives an immediate out without touching the toggle.
  • Where this lives: the Cockpit Settings page, in a Dictation group. The badge and suggestions panel never appear here - settings is for the rules, the Dictionary page is for the work.

The four decisions this round should settle

  1. How much evidence before we suggest? The screens assume: at least 3 wrong transcriptions of the same term, and wrong at least 25% of the times it was said. Lower catches more, earlier, but risks noisy suggestions that erode trust in the panel. My lean: start strict; loosening later is invisible, tightening later looks like the feature got worse.
  2. Does Add write corrections too? Screen 1 says yes: one press writes the term into Vocabulary AND its wrong spellings into Common mistranscriptions. The alternative - vocabulary only - is safer but leaves half the fix on the table. My lean: write both; the wrong spellings shown as evidence are exactly the correction entries.
  3. Default-on transcript storage? Screen 4 assumes on-by-default with a delete-on-opt-out switch. Default-off would make the whole feature invisible to the users it is meant to help, but default-on must survive the privacy review. My lean: default on, 30-day window, off-means-delete - the settings copy above is written to make that defensible.
  4. Email cadence. Screen 5 rides the daily report only when suggestions exist. Should a term that sits unreviewed for a week re-appear in the email, or is once per new batch enough? My lean: mention a given batch at most twice, then stay quiet until new evidence arrives - the badge keeps the durable signal.
