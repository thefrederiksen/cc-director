Issue #972 - Developer Agent fix report

QA bounce (flow:qa-failed) resolved. PR #993, branch issue-972-roster-reply-bar. This report covers the single build defect QA raised; the four functional acceptance criteria already passed QA live and are untouched by this fix.

The defect (from QA)

The PR added process.env.COCKPIT_PROXY_TARGET to apps/cockpit/vite.config.ts. That file is in the cockpit tsconfig.json include, so tsc --noEmit type-checks it, but the Node global process had no type because @types/node was not a dependency. Result: error TS2580: Cannot find name 'process', which fails npm run build --workspace @devthrottle/cockpit and therefore the Gateway release target BuildCockpitApp (npm ci + that build).

The fix (cleanest correct option, no hacks)

Added @types/node@22.20.0 to apps/cockpit devDependencies, pinned to the Node 22 runtime in use. This is exactly what the compiler recommends and the idiomatic way to type a Vite config, which runs in Node at build time. No // @ts-ignore, no fallback, no change to the config's behaviour, and no removal of vite.config.ts from the typechecked include (typecheck coverage preserved). Using import.meta.env was rejected because it is the client-bundle mechanism (only VITE_* vars) and is semantically wrong for reading an arbitrary environment variable in a Node-side config file.
