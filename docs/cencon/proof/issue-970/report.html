Issue #970 - Cockpit React: move server-side secrets and logic behind the Gateway

Developer Agent proof. Part of epic #967 (Cockpit React rebuild). Branch issue-970-gateway-secrets.

What was implemented

The React Cockpit is a browser single-page application that must hold no secret. The three things the Blazor Cockpit did server-side (because they need a secret or the Director host) were moved behind the Gateway:

  1. GitHub item status endpoint. New Gateway endpoint GET /gateway/lists/item-status?source&id resolving a work-list item's title + flow:*-derived status. The GitHub token is read on the Gateway host from the shared credentials file at point of use and never leaves the Gateway. Ported the Cockpit's GitHubItemStatusClient fetch + flow-label mapping into GitHubItemStatusResolver (injectable HttpClient + token provider for tests). Registered in GatewayHost next to the work-list routes, inheriting the host-wide token middleware.
  2. LinkDetector port. Hardened the client-core TypeScript port (packages/client-core/src/history/historyLinks.ts) so the History links do not diverge from the C# recognizer: added the drive-letter boundary guard (?<![A-Za-z]) and file:// URL handling (surfaced as local Path links), matching src/CcDirector.Core/Utilities/LinkDetector.cs. Added a vitest suite mirroring the applicable shared cases from the C# LinkDetectorTests.
  3. Brief fallback composition. Ported BriefFallback.FinalParagraph to a secret-free client-core function finalParagraph() (packages/client-core/src/brief/briefFallback.ts) with tests mirroring the C# BriefBuilderTests fallback cases.
  4. Browser API client. resolveItemStatus() (packages/client-core/src/api/itemStatus.ts) calls the new endpoint through a root-relative, same-origin path - no absolute host, no token (passes the Gateway-only-ingress lint rule).
