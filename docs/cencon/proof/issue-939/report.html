Issue #939 - Kill silent-failure paths + normalize 402 at the gateway boundary

Part of epic #937. Consumes the #938 foundation (merged to main). Branch issue-939-gateway-402-boundary.

What was implemented

Every gateway paid path now maps a runtime 402 into the ONE shared readiness state (branching on the machine code), and the two silent turn-end paths were ended - they record a visible, dismissible per-session state instead of swallowing the error.

FileChange
Gateway/HostedAi/HostedAiHttp.cs (new)The single place that turns a HostedAiState into its HTTP form: the wire DTO for /sessions and the shared 402 IResult. error mirrors the shared text so even un-updated clients show the right copy.
Gateway.Contracts/HostedAiMessageDto.cs (new)Plain-string wire carrier for the shared message (keeps Contracts free of a Core dependency).
Gateway.Contracts/SessionDto.csNew VoiceUnavailable field carrying the shared message for the owning UI.
Gateway/Api/GatewayWingmanVoiceEndpoint.cs/wingman/utterance + /wingman/transcribe: out-of-credits now returns 402 + shared message (was a generic 502). /wingman/tts: a 402 maps to the shared message (was "text-to-speech returned 402").
Gateway/Wingman/HostedInferenceBrain.csThe 402 message is now the shared copy, branched by code (previously it only checked the status, so it could not tell CapReached from NeedsCredits).
Gateway/Wingman/WingmanVoiceService.csC2 re-routed from a hardcoded OpenAI tts-1/nova call onto the configured provider seam (ResolveTts + TtsModelConfig/TtsVoiceConfig + the mode's vault key) - fixes the wrong-voice bug and makes hosted narration work for a DevThrottle-mode user. B8 no longer silent: turn-end failures record a per-session VoiceUnavailableFor state, cleared on the next success / OnSessionWorking / Unmark (dismissible).
Gateway/Api/GatewayEndpoints.cs + GatewayHost.csNew voiceUnavailableFor delegate (same pattern as voiceGeneratingFor) stamps SessionDto.VoiceUnavailable on the /sessions aggregation.
