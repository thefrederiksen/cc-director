Issue #940 - Consistent credits/key gating on the desktop (Avalonia) voice surfaces

Part of epic #937. Consumes the #938 foundation + #939 gateway work (both on main). Branch issue-940-desktop-credits-gating.

What was implemented

The native desktop app transcribes and synthesizes in-process and previously had no way to see the account balance (the account token is Gateway-only). This adds that, and wires every desktop voice surface to the ONE shared "add credits / add a key" message + call-to-action, so an out-of-credits or no-key user gets the consistent dialog instead of a raw 402 string or a silent nothing.

Message consistency is by construction

Every desktop surface shows the SAME HostedAiUnavailableDialog, which fills its text and button from HostedAiMessages.For(state) - the one source the phone and web also use. There is no per-surface hand-written credits/key string left in the desktop voice paths (the old bring-your-own-only string in FifoWindow was removed).

Manual verification checklist (native surface, per the epic's plan)

Forcing an out-of-credits / no-key state in a live desktop build is done as follows (QA runs this in an isolated slot; revert the config after):

  1. NeedsKey: set transcription_mode=byo with no OPENAI_API_KEY in the vault. Open the Speak dialog -> expect the shared "Add your OpenAI key in Settings" dialog with an "Add a key" button (no recording starts). Repeat via the takeover window's Ask.
  2. NeedsCredits: on a DevThrottle-mode account with a zero balance (a fresh test account on an enforce-mode preview), open Speak -> expect "Voice needs credit. Add $5..." with an "Add credits" button that opens the billing page.
  3. Runtime 402: with a balance just above one call, run dry mid-dictation -> expect the same dialog (not a raw "Transcription returned 402").
  4. Read-aloud 402: trigger the Voice tab / takeover read-aloud out of credits -> expect the shared dialog rather than silence.
  5. Add-$5: from the NeedsCredits state, add credit and retry without restarting the app -> the feature works (balance re-read on the next check).

CenCon impact

No architecture or security drift. The desktop reads the balance through the existing token-free /account/credits endpoint (the account token stays on the Gateway; nothing new is logged, DT-05). No new egress host - the billing URL resolves from the foundation's HostedAiUrls, and Cockpit via the existing front-door probe. OpenAiTtsService (C5) is not reached by any desktop surface and was left out of scope.

I believe the desktop wiring is complete and building; the live visual states are verified via the checklist above.
