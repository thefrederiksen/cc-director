QA Proof - Issue #906

Title: The installer's forced sign-in was saved to the Director store (which the Director deletes on startup and the Gateway never reads), so the user was prompted to sign in again on first Gateway launch.

Branch: issue-906-installer-gateway-signin   PR: #907   Commit under test: 22065778

Verifier: QA Agent (independent). Built and tested in an isolated worktree on the PR branch HEAD - not the Developer's binary.

Verification method

Independent checkout of the PR branch in a fresh worktree, clean build of the full solution, and independent re-run of the three affected test suites. This issue changes only where the installer persists the captured sign-in credential; it has no Director product-behaviour surface to drive, so verification is by clean build, the automated cross-boundary tests, and code inspection of the persist target and every log call (DT-05).

The load-bearing structural fact was confirmed directly in source: the installer now writes through CcStorage.GatewayDevThrottleCredentialBlob() (config/gateway/devthrottle-credential.bin), which is the exact path GatewayAccountFactory.CreateForWindows() reads on first launch (src/CcDirector.Gateway/Account/GatewayAccountFactory.cs:53). Same store type, same path - so a credential the installer writes is the credential the Gateway reads.
