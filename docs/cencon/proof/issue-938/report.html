Issue #938 - Shared hosted-AI readiness check + single-source message copy

Foundation sub-issue of epic #937 (consistent "hosted AI needs credits or a key" gating across every voice / Wingman / text-to-speech surface). Branch issue-938-hosted-ai-readiness.

What was implemented

The single primitive the ~13 voice / Wingman / text-to-speech surfaces will consume, so the "you need credit / you need a key" gate is decided in one place and shown identically everywhere by construction. Hung on the existing centralized routing seam (TranscriptionMode + TranscriptionEndpointResolver), it is pure and delegate-injected in Core, with the real-resource wiring in the Gateway.

FileRole
src/CcDirector.Core/HostedAi/HostedAiState.csThe one typed answer: Ready | NeedsCredits | CapReached | NeedsKey.
src/CcDirector.Core/HostedAi/HostedAiReadiness.csThe pre-flight check. CheckAsync() resolves mode -> state; balance is read fresh every call (no cache) so adding $5 unlocks with no restart.
src/CcDirector.Core/HostedAi/HostedAiMessages.csSingle-source copy: For(state) returns one message + call-to-action per state. Plus HostedAiCopyRules, the forbidden-language checker.

src/CcDirector.Gateway/HostedAi/GatewayHostedAi.csWires the Core check to the real vault + account credential + credits client. The factory the platform sub-issues (#939-#943) call.
src/CcDirector.Core/Transcription/BatchTranscriptionPipeline.csRefactored: its private 402 code parse now delegates to HostedAiErrorMapper.ParseErrorCode, so the whole stack parses a 402 in exactly one place.

CenCon impact

No architecture or security drift. This adds one pure Core module plus a thin Gateway factory on the existing transcription seam; it introduces no new container, no new egress host (the Billing URL resolves from the existing account-egress base), and touches no security rule. The account token is read only through the existing GetAccessTokenForForwarding and is never logged (DT-05).

Scope note

Per the issue's Scope (OUT), this delivers the shared primitive only; wiring the individual surfaces is the per-platform sub-issues #939-#943. No surface behavior changed in this issue except the internal 402-parse consolidation.
