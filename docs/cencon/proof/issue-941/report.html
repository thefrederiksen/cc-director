Issue #941 - Consistent credits/key gating on the web (Cockpit + Director web) voice surfaces

Part of epic #937. Branch issue-941-web-credits-gating. Foundation #938 + gateway #939 + desktop #940 already on main.

Approach

The web surfaces display the server's error field raw, so the highest-leverage fix is server-side: every Director endpoint the web calls now maps a hosted-proxy 402 to the ONE shared payload, whose error field mirrors the shared message text. That makes the correct "Voice needs credit. Add $5..." message appear by construction; the two surfaces that previously HID the failure got a small client fix.

What was implemented

FileChange
Core/HostedAi/HostedAiPayload.cs (new)The single wire shape (pure, no ASP.NET) shared by the Gateway, the Control API, and the WebSocket frame; error mirrors the shared text; JSON names pinned.
Gateway/HostedAi/HostedAiHttp.csRefactored to build the 402 from HostedAiPayload - Gateway and Control API now return the identical body (behavior-identical to #939).
ControlApi/DictationEndpoint.cs (A1/A2)The /dictate WebSocket now sends the shared message + hostedAi payload on out-of-credits, instead of "transcription failed: ...402...".
Core/Voice/VoiceService.cs + ControlApi/ControlEndpoints.cs (A3)The Voice-tab transcription (/voice/utterance/complete) carries the 402 code and returns the shared 402 payload; the client (session-view) shows the shared message.
ControlApi/ControlEndpoints.cs + Web/session-view.html (C3)Director /tts returns the shared 402; the web player shows the message instead of silently falling back to the robotic browser voice.

Coverage note (honest scope)

Wired the real credits-bearing web surfaces: dictation (A1 Cockpit composer + A2 session-view composer, both via /dictate), Voice-tab transcription (A3), and Director-web read-aloud (C3). Not wired: B4 (Cockpit voice.js wmAsk) and B5 (Cockpit Learning "Ask Wingman") - both call the warm claude.exe wingman, NOT the hosted credit proxy, so they never produce a real out-of-credits 402 (the map confirmed this). Their dictation input still flows through /dictate, which IS covered. The old Blazor Cockpit is still live (the React apps/cockpit is a placeholder stub), so wiring it was worthwhile.
