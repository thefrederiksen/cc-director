Issue #1082 - Stop returning access/refresh tokens in the sign-in callback URL query string

Epic #1069 - absorbs #877 - Developer Agent proof - branch issue-1082-callback-no-token-query

I believe this is finished. The credential hand-back no longer rides in the callback URL query string on either sign-in callback surface. The token pair is carried in the URL fragment (which the browser never sends to a server); the callback serves a small hand-back page whose script reads the fragment and POSTs the pair back same-origin as a request body, which the server captures. The old query-string shape is still accepted during the cloud-side transition. Every acceptance criterion is proven below with a live run and passing tests.

What was implemented

  • New shared page src/CcDirector.Core/Account/CredentialHandbackPage.cs - the fragment-reading hand-back page (its script reads location.hash, POSTs the pair back same-origin, and strips the fragment from the address bar) plus TryParseJsonBody. Mirrors the phone's existing fragment pattern (packages/client-core/src/auth/DeviceCallback.tsx).
  • Host-local loopback listener src/CcDirector.Core/Account/LoopbackLoginListener.cs - WaitForCredentialAsync now captures the credential from the same-origin POST body (new shape), serves the hand-back page on a bare GET, still accepts the token pair in the query string (transition), and fails loud when neither shape yields both tokens.
  • Reachable front-door callback src/CcDirector.Gateway/Api/AccountSignInCallbackEndpoint.cs - added a POST handler that captures the pair from the request body; the GET serves the hand-back page when no token is in the URL and still completes the old query-string shape during transition.
  • Local sign-in stand-in tools/devthrottle-dev-signin/Program.cs - the local stand-in for the devthrottle.com completion page now redirects with the token pair in the URL fragment (not the query), so the end-to-end loopback flow is provably token-free in this repository.
  • Tests - new-shape (body) capture, old-shape (query) transition, and incomplete-credential failure for both surfaces, plus a focused test of the shared page/parser.

CenCon impact

No architecture drift: no container added or removed; the affected containers (CcDirector.Core, CcDirector.Gateway) keep their responsibilities. This strengthens the security posture - it removes the long-lived refresh token (and the access token) from the callback URL, so neither lands in browser history, screenshots, or the address bar. Security rule DT-05 (no token material in logs) is upheld on every path, proven above. No blocking security rule is violated. There is no docs/cencon/architecture_manifest.yaml or security_profile.yaml in the repository to update.
