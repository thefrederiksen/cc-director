Note on the harness (NOT a product defect): CockpitSupervisor.KillOrphans() kills every
process named "devthrottle-cockpit" machine-wide by name. Running a second MANAGED Gateway
next to the user's live Gateway makes the two supervisors kill each other's Cockpit child in a
loop. This is pre-existing supervision behavior unrelated to the #920 diff (which is purely
AuthMiddleware routing + a Cockpit-side Bearer). Verified around it by running the Cockpit
under a distinct process name, unmanaged; the circuit is then stable.
