Proof of Completion - Issue #1074

[Core] Extend cloud access-token validation with audience, issuer, and subject claim checks for authorization use. Part of epic #1069 (Phase 1).

Release Notes

The local cloud access-token validator now offers an authorization-grade validation path. On top of the existing signature and expiry (exp) checks used to authorize the Gateway's own outbound cloud calls, it can now also verify the audience (aud), issuer (iss), and not-before (nbf) claims and extract the subject (sub). This is the foundation for using a cloud session as a first-class inbound credential (epic #1069): a correctly-signed token minted for a different audience or issuer is now rejected, a not-yet-valid token is honoured, and the account subject is exposed so a later membership check (issue #1079) can confirm the token belongs to this Gateway's account. Validation remains fully local - no per-request cloud call - so the Gateway keeps working during a cloud outage.

Changes

  • src/CcDirector.Core/Account/JwtAccessTokenValidator.cs
    • Added a new AuthorizationTokenValidation result record (IsValid, Subject, ExpiresAtUtc, InvalidReason).
    • Added the ValidateForAuthorization(string accessToken) method: signature + exp + nbf + aud + iss + non-empty sub.
    • Added two optional constructor parameters, expectedAudience and expectedIssuer, mirroring how signingSecret and publicKeySetJson are supplied (configuration, not hard-coded at the call site). Existing constructor call sites are unaffected (all pass the first argument positionally and the rest by name).
    • Extracted the shared VerifySignature path so both Validate and ValidateForAuthorization use the identical, fully-local signature code path. The existing Validate(...) behaviour is unchanged (proven by the pre-existing tests still passing).
    • Audience matching accepts both the single-string and array forms of the aud claim (RFC 7519).
  • src/CcDirector.Core.Tests/Account/Es256TestKey.cs - added CreateAuthorizationToken(...) to mint ES256 tokens carrying the aud/iss/sub/nbf claims (single-string or array audience).
  • src/CcDirector.Core.Tests/Account/JwtAccessTokenValidatorAuthorizationTests.cs - new test class (8 tests).
