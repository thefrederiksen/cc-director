Issue #1079 - Gateway account-membership check

Epic: #1069 (Phase 1)  |  Builds on: #1074 (authorization-grade claim checks)  |  Branch: issue-1079-account-membership

What this adds. Once #1074 validates a presented cloud access token for authorization use (signature, audience, issuer, not-before, expiry) and extracts its stable subject, this issue adds the membership check: the Gateway accepts the token only when its subject equals the account THIS Gateway is signed in to. A perfectly valid token minted for a DIFFERENT DevThrottle account is refused, and a signed-out Gateway accepts no cloud session. This is the account-level ownership gate that lets #1c later wire a cloud session into AuthMiddleware. No request-pipeline change is made here.

What was implemented

LayerFileChange
Coresrc/CcDirector.Core/Account/JwtIdentityReader.cs New ReadSubject(accessToken) - reads the stable sub claim locally (no network); never logs the subject value.
Coresrc/CcDirector.Core/Account/DevThrottleAccountService.cs New public GetAccountSubject() - the Gateway's own account key, read from the same cached credential GetIdentity uses (no network); logs only whether one resolved, never the value.
Gatewaysrc/CcDirector.Gateway/Account/GatewayAccountMembership.cs New membership-check component + AccountMembershipResult record. Check(AuthorizationTokenValidation) accepts only on subject equality; refuses on mismatch, on a not-valid presented token, or when the Gateway is signed out. PII-free accept/refuse logging.
