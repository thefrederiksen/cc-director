Proof - issue #1318 (consumer): email the account owner from a session/scheduled run

The escalation channel for Auto Daily Runs. The cloud send primitive shipped as devthrottle_internal #338; this is the DevThrottle-side consumer that calls it. The Gateway holds NO Resend key - it only relays the account's own token.

What was implemented

  • CcDirector.Core/Account/AccountNotifyClient.cs - cloud client for POST /api/v1/account/notify-owner, Bearer account token, body carries subject/text/html/attachments and NO recipient (single-recipient by construction). Token never logged; base URL resolved via the shared account-egress resolution.
  • CcDirector.Gateway/Api/AccountEmailEndpoint.cs - POST /account/email relay: injects GetAccessTokenForForwarding() and forwards to the cloud. Signed-out -> 401, cloud failure -> 502, never a fabricated success. Token-gated like the other /account routes.
  • cc-devthrottle email owner --subject --body [--html] [--attach <file>] - the CLI verb; --attach is repeatable, reads the file and base64-encodes it with a guessed MIME type (e.g. an HTML report to read offline).
