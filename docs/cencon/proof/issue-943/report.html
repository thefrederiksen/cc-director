Issue #943 - Consistent credits/key gating on the native Android (MAUI) app

Part of epic #937 - the final surface. Branch issue-943-android-credits-gating. App: phone/CcDirectorClient.

Audit (AC 1) - current no-credit / no-key handling before this change

  • The app does NOT reference CcDirector.Core (standalone MAUI project) and shouldn't - Core is a heavy Windows-shaped assembly (DPAPI/SQLite/YAML). So the phone parses the server's shared 402 body rather than importing the message table - nothing to keep in step.
  • No central HTTP wrapper; Voice/DirectorVoiceClient.cs is the seam for transcription (/voice/utterance/complete) and read-aloud (/tts). Both threw a raw HttpRequestException("...failed: 402 {json}") on 402 - no credits awareness anywhere in phone/.
  • Surfaces: SpeakIntoTextboxDialog showed the raw message in a hint label; TalkPage showed DisplayAlert("Voice error", ex.Message); VoiceSessionView showed the turn error in an alert AND silently swallowed a briefing-TTS failure (logged only, briefing showed "-"). AndroidReplySpeaker is a playback sink (no HTTP) - no change needed.
  • No Launcher.OpenAsync usage existed (billing deep-link is net-new); no account/credits concept.

What was implemented (AC 2)

FileChange
Voice/HostedAiUnavailable.cs (new)HostedAiUnavailableException (carries the server's shared text/ctaLabel/ctaUrl/state; TryFrom(status, body) parses the shared 402 body) + HostedAiPrompt.ShowAsync(page, ex) (shows the message, and on confirm opens Billing via Launcher.Default.OpenAsync).
Voice/DirectorVoiceClient.csTranscribeUtteranceAsync and SynthesizeSpeechAsync throw the typed exception on 402 (parsing the shared body) instead of a raw "failed: 402".
TalkPage.xaml.csCatches the typed exception and shows the shared add-credits prompt.
Controls/VoiceSessionView.xaml.csTurn catch shows the shared prompt; the previously SILENT briefing-TTS catch now surfaces it too.
