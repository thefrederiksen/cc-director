Summary

Three distinct sources of red/flaky .NET tests were root-caused and fixed properly and deterministically - no [Skip], no quarantine, no try-catch swallow, no weakened coverage. All fixes are in the test layer because every failure was a test-hermeticity defect (a test depending on ambient machine state), not a product bug. No production code was changed.

#Test(s)SymptomRoot causeFixStatus
1 NoCrossMachineLoopbackGuardTests.No_new_production_file_hardcodes_cross_machine_loopback (Core.Tests) - the "loopback-guard" test Hard-fail on clean main Two production files added a loopback literal (GatewayConfig.cs, DesktopHostedAiCta.cs) after the allowlist was last updated. The fitness-function guard is designed to fail until each new file is triaged and allowlisted. Verified each is a legitimate SAME-machine use (a local-Gateway host classifier; doc comments stating the desktop never opens a localhost URL) and added both to the allowlist with reasons - the exact mechanism the test documents. FIXED
2 BrowserPageRoutesTests shell-path tests (Gateway.Tests) - the "environmentally-flaky" one Intermittent red depending on the machine/build config The tests hard-asserted 404 "React Cockpit not built", which only holds when wwwroot/c (the release-gated, gitignored React bundle) is absent. A Release/BuildCockpit build stages it and the shell path returns 200 text/html instead - flipping the assertion. Assert the environment-independent invariant (a browser navigation is served the shell, never the JSON endpoint) and branch the concrete shape on the same CockpitReactApp.WebRoot presence the production router reads. Deterministic whether or not the bundle is staged; full coverage kept in both states. FIXED
3 DispatchEndpointTests, ExecuteActionEndpointTests, ToolRunEndpointTests, SessionNumberBackfillTests.BackfillEndpoint_RequiresBearerToken_WhenAuthEnabled (Gateway.Tests) Whole classes intermittently red as a block (~1 in 10 full runs); every test got 401 Unauthorized instead of its expected status An auth-enabled ControlApiHost resolves its accepted token from GatewayConfig.Load().Token - the machine-global config.json. On a fleet machine whose config carries a gateway.token, the host accepts that fleet token while the test client presents the local gateway-token.txt token - a mismatch that 401s every authed call. These four spots forgot the CC_DIRECTOR_ROOT isolation their sibling fixtures use. Redirect CC_DIRECTOR_ROOT to a fresh temp dir in each fixture (matching the established AgentsEndpointTests idiom), so the host sees an empty config (no fleet token) and host + client resolve the same isolated token. Restored in dispose. FIXED

Deterministic reproduction proof (flake #3)

The fixed classes pass because each redirects to its own fresh root. See gateway-poisoned-root-proof.txt:
