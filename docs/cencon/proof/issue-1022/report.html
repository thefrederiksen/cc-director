Proof - Issue #1022

Cockpit QA fix: remove the dead "Awareness" right-rail placeholder that shipped on every page, and stop the interactive terminal silently clipping its right edge. Follow-up to epic #967.

Surface: React desktop Cockpit (apps/cockpit) Branch: issue-1022-cockpit-rail-terminal-clip

What was implemented

FileChange
apps/cockpit/src/AppShell.tsx Removed the static <aside class="rail rail-right"> that rendered the placeholder text "Turn rail and awareness panes land here." on every route. The shell is now a two-region frame (left rail + main pane). The framing comment was rewritten to record why there is intentionally no static right rail.
apps/cockpit/src/styles.css Shell grid dropped from three columns to var(--rail-left-width) 1fr, so the main pane reclaims the ~300px the dead rail stole. Removed the now-dead --rail-right-width token and the .rail-right, .rail-title, .rail-empty rules and the tablet-breakpoint rail-right fold. Changed .term-host from overflow: hidden to overflow-x: auto; overflow-y: hidden so a PTY grid wider than the pane is horizontally scrollable (reachable) instead of silently clipped - xterm still owns vertical scrolling. Hardened .term-bar-sid (the terminal status line) with flex: 0 1 auto; min-width: 0 so a long session id ellipsizes inside the bar instead of overflowing the pane edge.

The engine (packages/client-core/src/terminal/interactive.ts) was deliberately left unchanged: its documented invariant is that xterm mirrors the PTY grid EXACTLY (both cols and rows) to avoid TUI ghosting. The issue explicitly sanctioned the "make .term-host horizontally scrollable" alternative, which fixes the silent clip without touching that invariant.
