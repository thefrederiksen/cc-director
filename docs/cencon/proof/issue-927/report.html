Issue #927 - Tray "Restart Gateway": visible success/failure confirmation

Epic: #916 (Phase 5, independent of auth). Branch: issue-927-restart-feedback. Scope: restart FEEDBACK only - the in-process stop/start is unchanged.

What was implemented

  • New pure string builder src/CcDirector.Gateway/Tray/GatewayRestartFeedback.cs - builds the exact SUCCESS/FAILURE wording (tooltip + flyout status) including the running version and time. No Avalonia, no I/O, so it is fully unit-tested off the UI thread (mirrors GatewayTrayFlyoutCache).
  • Wired into src/CcDirector.GatewayApp/GatewayTrayController.cs:
    • RestartAsync now reads the outcome after the (unchanged) stop/start chain - HostState.Running = success, otherwise failure - and shows a distinct confirmation.
    • On SUCCESS: a distinct tray tooltip "restarted OK (v<version>) at <time>" that reverts to the normal running tooltip after an 8-second dwell, plus a persistent "Last restart" row at the top of the flyout as the durable record.
    • On FAILURE: a distinct tooltip "RESTART FAILED: <reason>" and a persistent "Last restart - Restart FAILED ..." row (never a silent no-op). A boundary catch also surfaces any throw.
    • Logged via FileLog (entry/success/failure) and non-blocking: all UI updates go through ApplyStatus, which posts to the UI thread; the tooltip revert is fire-and-forget.
