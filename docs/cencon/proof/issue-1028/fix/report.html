Issue #1028 - Developer Agent re-hand-off (QA bounce fix)

PR: #1042   Branch: issue-1028-cockpit-error-states   Epic: #967

The QA defect

The prior hand-off wired the shared gatewayErrorMessage() helper into only the fleet, directors, sessions, and telemetry views. QA proved acceptance criterion 2 ("No page shows a raw GET /path failed: NNN string") still failed: under a forced 503, Lists rendered Gateway error: GET /lists failed: 503, Schedule rendered Gateway error: GET /cron/jobs failed: 503, and Account rendered Could not load account status from the Gateway: GET /account/status failed: 503. Criteria 1 (telemetry save), 3 (Director-detail error state), and 4 (cold roster) passed and were not touched.

The fix - comprehensive audit

Every page and component in apps/cockpit/src that renders a Gateway error to the user was audited and routed through the existing gatewayErrorMessage() helper (or, where a page keeps an action-context prefix such as "Add item failed:", the raw detail inside the prefix was replaced by the helper's friendly line). No page now renders a thrown GatewayError.message or the browser's bare "Failed to fetch" verbatim.

18 files changed (mechanical routing only, no behaviour/logic change beyond the message text):

  • Load/banner pages QA named: ListsView, ScheduleView, AccountView.
  • Other pages that still leaked identically: AboutView, WingmanQueueView, FeedbackView, DictionaryView, ExesView, TranscriptsView, NewSessionDialog.
  • Session panes/components: AwarenessPane, BriefPane, SessionActionBar, ScreenshotsPanel, QueuePanel, SessionComposer.
  • SettingsView: its single errText() helper now delegates to gatewayErrorMessage(), routing all of that page's messages in one place.
  • client-core LearningView data path: learningClient.askDevThrottle()'s network-exception branch now returns the friendly transport line instead of the browser's raw "Failed to fetch".

Already-correct on the branch and left unchanged (verified): FleetView, DirectorsView, DirectorDetailView, SessionsView (helper already applied), and TelemetryView (fixed friendly boolean flags - criterion 1, not regressed).
