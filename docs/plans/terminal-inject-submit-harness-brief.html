CC Director · engineering plan brief

Making text injection into agent terminals reliable

We send text into a coding agent's terminal and press Enter for it. The Enter keeps getting lost, so the message sits in the composer unsubmitted and the agent looks idle. This is how we fix it and prove it fixed.

Full plan: docs/plans/terminal-inject-submit-harness.md  ·  merged from a Claude and a Codex pass

send text → lands in composer → press Enter → Enter lost to redraw → prompt parked

The signature. The text almost always arrives. What fails is the submit: the Enter reaches the agent mid-repaint and is swallowed. Worst for the fleet/REST route into Codex, and for large pastes into Claude (its composer expands, and the Enter fires before it is ready).

01 The core idea

Treat submit as a verified protocol, not a blind write

A blind "type, wait 50 ms, press Enter" loses a race against the agent redrawing its composer. Instead, every submit runs one tested handshake for every agent — one shared base, not a copy per driver:

  1. Type the text — write the payload, but do not send Enter yet.
  2. Wait for the echo — poll the terminal until the composer shows back what we typed (and is not slash-corrupted). The agent has told us it is ready.
  3. Press Enter separately — a lone carriage return, after a tiny settle, once the echo confirms.
  4. Confirm the turn started — watch for the agent to actually begin processing; if not, one clean retry, then a loud, logged failure — never a silent park.

02 Handling size and shape

Small / inline

The echo-verified handshake above. Already proven for Claude, Codex, and Pi; we extend the same base to the agents still doing blind writes.

Large / multi-line

Send it as one atomic bracketed paste (ESC[200~ … ESC[201~), then Enter outside the brackets — the agent takes the whole block and decides when to submit, so nothing auto-submits on an interior newline.

Gated on the agent actually having paste-mode on; the temp-file reference stays as the fallback.

03 Prove it — at the turn level

A test that checks "we wrote the bytes" is worthless; that always passes. Green requires proof from the agent's own behavior:

  • Sentinel token — the injected prompt asks the agent to reply with a known token; we watch for it. End-to-end proof, even for agents with no transcript.
  • Transcript delta — for Claude and Codex, a genuinely new message appears in their own history file.
  • Parked-composer detector — on timeout we check if our text is still sitting in the box with no turn started, and classify it parked_composer instead of a vague failure.
  • Flake rate, not a single run — each case runs many times; reliability is a percentage that must hit 100% / 20 runs, because one green run is exactly how this bug hides.

04 Once, or per agent?

We don't guess — the harness measures it. It runs every agent through the same matrix across four routes (direct, REST, fleet, voice) and compares submit strategies head to head (current, echo-verified, bracketed-paste, blind). If one strategy hits zero flake for everyone, we collapse onto one shared base. Where an agent genuinely differs, the data says so — and that divergence is justified by evidence, not folklore.

05 How we roll it out

  1. Characterize today, deterministically

    ends: dotnet test reproduces the lost-Enter race on a fake terminal

  2. Live proof for Claude and Codex

    ends: a real report on this machine, direct + REST + fleet routes

  3. The hard cases + bracketed paste

    ends: report says which strategy wins large / multi-line, per agent

  4. Fan out to every installed agent

    ends: strategy + flake-rate tables across the full matrix

  5. Decide, change the submit code, gate it

    ends: the fix shipped, with the harness keeping the flake rate at zero

Bottom line: stop blind-firing Enter. Type, wait for the agent to echo, then submit and confirm the turn actually started — the same verified handshake for every agent, with bracketed paste for big blocks — and let a live, per-agent test harness prove the flake rate is zero before and after we touch the code.
