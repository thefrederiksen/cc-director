Mission: Stable Release

DevThrottle v1.3.0 · Mission ac6883bb-09e2-4b5a-96bf-df3eae8d9f63 · 2026-07-14

Why this mission exists

Yesterday cost the owner a full day of work he could not do, because DevThrottle told him things that were not true.

A stale executable reported the same version number as a fixed one, so nobody could tell which build they were running. Session rename answered "not found" with no explanation. Agents were reading a skill that documented an interface deleted weeks earlier. Each failure was small. Together they made the tool untrustworthy, and an untrustworthy tool cannot be used to build anything.

v1.3.0 is not a feature release. It is the release where DevThrottle stops lying. Every item below either removes something that misleads, or makes a failure explain itself.

The finish line

v1.3.0 is published, and on a bad mobile connection in a moving car the tool either works or says plainly what went wrong. No raw 500s. No silent hangs. No document or skill describing an interface that does not exist. No open inbound port that nothing dials.

Already banked in v1.2.0 (merged, awaiting its tag). Session rename and close repaired; the full session-control surface restored to agents (prompt, interrupt, hold, buffer, role); the tunnel large-reply fix; Tailscale made optional; macOS support; one hold state machine shared by desktop and phone; and the version number made honest again.

Tier 1  Stability - these ship

1. A dropped command must explain itself

A tunnel drop mid-command surfaces as a raw HTTP 500, and most hot-path commands are awaited with no timeout at all. On a weak mobile link that is an indefinite hang with no explanation. Both reviews rank this the single highest-value fix for the driving case. Add a command timeout and a typed error that names what happened.

2. Close the open inbound port

LAN addressing mode binds the Director to 0.0.0.0, directly contradicting the tunnel-only cut's stated invariant that the inbound port stays closed. Nothing dials it anymore, so it is pure attack surface with no user.

3. Cockpit Director Settings is broken (#1508)

/directors/{id}/settings returns an HTML shell. The same disease as rename: a caller left pointing at something the cut moved.

4. "Verify now" can never succeed

The desktop button still posts to a Gateway verify endpoint deleted in the cut. A button that cannot work is worse than no button.

Tier 2  Cleanup - statically safe, no behaviour change

5. Delete the dead code both reviews name

The register and heartbeat cluster inside GatewayClient; DirectorForwarding and the unused forwarder registration; the orphaned DispatchContracts; the CockpitWsUrls and CockpitShotUrls contracts; the now-inert streamMode configuration key; and the never-assigned _serveProvisioner field with its dependent branches.

6. Fix the public API reference

docs/public/api/01-control-api.md still describes sessions, prompts, buffers, git and handover endpoints on the Director. The Director floor has about a dozen routes. This document is public and is actively misleading anyone reading it today - it is the same failure mode that cost the owner yesterday, still live.

7. Delete the documents describing worlds that never shipped

Five architecture documents describe designs that were never built or are fully dead. They have no salvage value and every one of them is a trap for the next reader.

Rules for this mission

  1. Verify before you claim. Every finding here was checked against origin/main, not a commit message and not a memory. A checkout, a CLI, and a running Director can each lag main and contradict the code.
  2. Probe the route, never the version. /healthz cannot tell a fixed build from a broken one. Probe the real route against a deliberately fake one. Never probe /fleet/spawn - it returns 201 and creates a real session.
  3. Proof is a running build, not a green test. Every Tier 1 item is demonstrated on a slot Director before it is called done.
  4. No fallbacks. Fix the root cause or fail loudly with a clear message.
  5. Plain English, ASCII only. No abbreviations, no jargon, no emoji.
  6. The human publishes the tag. Everything is prepared; the final irreversible click is the owner's.

Order of work

  1. Tier 1 item 1 - the command timeout and typed error. Largest effect, smallest change.
  2. Tier 1 items 2 to 4 - each proven on a running slot.
  3. Tier 2 item 5 - one focused deletion pull request, statically safe.
  4. Tier 2 items 6 and 7 - the documents that mislead today.
  5. Cut v1.3.0: bump Directory.Build.props, write the notes, accuracy-gate them, open the release pull request. The owner publishes the tag.

Release mechanics, so nobody rediscovers them. The version lives in exactly one file, Directory.Build.props. scripts/new-release.ps1 does not work - it direct-pushes main, which is branch-protected (#1133). The bump reaches main through an ordinary pull request; the tag is then cut on main at the merged commit, and pushing it triggers the Release workflow. Full run-book: the release-manager skill.
