1. `src/CcDirector.Core/Sessions/InjectedTextStore.cs:157` fetches `/gateway/injected-text` with a bare `HttpClient`, so secured Gateways will reject the refresh with 401 and the Director cache will never warm. Existing Gateway calls attach the configured Bearer token (`src/CcDirector.ControlApi/GatewayClient.cs:125` to `129`), and the Gateway auth gate expects that header (`src/CcDirector.Gateway/Util/AuthMiddleware.cs:196` to `207`). Because `ControlApiHost` swallows refresh failures (`src/CcDirector.ControlApi/ControlApiHost.cs:253` to `259`), an opted-out user on a fresh/no-cache Director silently gets the no-cache default path (`ActiveSource`/`ActiveTemplate` read as ours) instead of the Gateway-owned choice. 2. `src/CcDirector.ControlApi/ControlApiHost.cs:227` to `230` refreshes the Director cache only when the connection state changes to `Connected`. A Cockpit save goes through `PUT /gateway/injected-text` and persists the new Gateway-owned value (`src/CcDirector.Gateway/Api/SettingsEndpoints.cs:304` to `325`), but an already-connected Director receives no event and does not refresh again. New sessions on that Director keep injecting the old cached text until a reconnect/restart happens. For this setting, that can leave DevThrottle text active after the user just saved an empty/custom text, which is the exact degraded-cache failure mode this change is trying to avoid. Add a stale/read-triggered refresh, a periodic refresh like the snooze cache, or a Gateway-to-Director invalidation path; then cover "save while connected, next launch sees new value."

3. `src/CcDirector.Gateway/Api/SettingsEndpoints.cs:313` treats a missing `use_yours` as `false`, and the body model also cannot distinguish absent `yours` from explicit `null` (`src/CcDirector.Gateway/Api/SettingsEndpoints.cs:663` to `665`). That means a malformed or partial `PUT { "yours": "..." }` silently writes `use_yours=false`, and `PUT { "use_yours": false }` silently persists `yours=null`, erasing the saved custom text instead of failing the required `{ use_yours, yours }` contract documented above the endpoint. Since null/absent carries different meaning from empty string for this feature, the endpoint should reject missing required fields rather than defaulting them before validation.
