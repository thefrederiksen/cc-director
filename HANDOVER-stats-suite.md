## The two remaining pieces

### 1. Adoption accepts versions 5 through 7

Ruled by the Architect. The constant was never meant to say "five" — it means *the shapes the old code wrote,
which exist on disks and cannot be changed retroactively*. That is three shapes, not one: the shipped
hand-rolled code has `MigrateToVersion6` and `MigrateToVersion7`, so real files are at 5, 6 or 7 depending on
when they were last opened. Refusing 6 and 7 does not protect anyone from a newer build; it refuses the
ordinary present.

**The stamp must be version-dependent, and this is what makes it correct rather than a loosening.** Adoption's
claim is "this file already has the shape these migrations would produce". So a version 5 file stamps the
baseline only; a version 6 file stamps baseline + v6; a version 7 file stamps baseline + v6 + v7. Stamping
only the baseline on a version 7 file would tell Entity Framework the file lacks work it already has, and the
chain would then try to add columns and indexes that are there.

Anything above 7 still refuses with `StoreIsNewerThanThisBuild`.

**Proof obligation:** the baseline-equivalence method runs three times, once per adoptable version — build a
real file with the old code at 5, at 6 and at 7, and diff each against baseline, baseline + v6, and
baseline + v6 + v7 respectively. Same method that already works, three fixtures instead of one.

Touch points: `GatewayStatsSqliteAdoption.LegacyBaselineSchemaVersion`, the version gate around line 186,
`BaselineMigrationOf` / `Stamp`, and the `DescribeMismatch` expected-shape comparison.

### 2. Finish the aggregator port

**Hosted has no statistics surface at all — not a broken one.** `GatewayInputStatsAggregator` still has four
raw `_db.Connection` sites and two `SqliteTransaction` signatures, and *both* constructors require
`GatewayStatsDatabase`, which is SQLite-specific. It cannot be constructed over Postgres. Worker 3 ported the
twelve read projections to Entity Framework; the fold path was never finished.

So this is not "point the stats page at the Postgres store" — that framing is wrong and was believed by more
than one person tonight. It needs a provider-neutral constructor and the last four raw sites removed.

**This is the WRITE path. Getting it wrong yields wrong numbers, not an error.** Weigh that against the fact
that hosted currently records nothing at all.

Related: `GatewayHost.OpenInputStats` deliberately constructs nothing on hosted, and `/stats` answers 503 with
a named reason. That containment is correct and should stay; what changes is that there is finally something
to construct.
